# @office-worms/client

Локальный браузерный клиент для визуальной проверки game-core. В одной вкладке два игрока
по очереди управляют своими командами. Игровые правила полностью рассчитывает ядро.

## Запуск и сборка

Из корня репозитория:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:4173. Другой порт: `npm run dev -- --port 4174`.
При EPERM на workspace-ссылках установка допускает `npm ci --workspaces=false`.

`npm run build` собирает оба пакета и копирует браузерные ресурсы в `packages/client/dist`.
Внутри — index.html, styles.css, модули клиента и `core/` со сборкой game-core.
Результат самодостаточен: каталог можно раздавать обычным статическим HTTP-сервером.
`npm run preview` запускает такую раздачу; предварительно требуется сборка.

Dev-режим следит за `packages/game-core/src`, `packages/client/src` и `packages/client/public`.
После успешной пересборки посылает перезагрузку через локальный SSE-канал.
Матч при перезагрузке сбрасывается. Изменения конфигурации сборки требуют перезапуска dev-сервера.

## Управление

| Действие | Как выполнить |
| --- | --- |
| Начать ход | Кнопка «Начать ход»; до неё таймер не работает |
| Ходить | Удерживать A/D, ←/→ или кнопку направления на панели |
| Прыгнуть | W, ↑ или кнопка «Прыжок»; повтор возможен после приземления |
| Прицелиться | Ползунок угла или клик по полю относительно активного червя |
| Задать силу | Ползунок 0..100%; ноль соответствует минимальной скорости базуки |
| Выстрелить | «Огонь» или Space, если фокус вне элементов управления |
| Пропустить | «Пропустить ход» во время активного хода |
| Новый матч | Выбрать карту/ветер, нажать «Перезапустить матч» |

После начала хода фокус переходит на поле. Клик по полю возвращает управление клавиатурой.
Клавиши работают по физическим кодам и при русской раскладке; ввод в полях и ползунках не перехватывается.
Последнее нажатое направление имеет приоритет; после отпускания возвращается предыдущее удерживаемое.
Потеря фокуса поля/окна, скрытие вкладки, пауза, смена хода и сброс матча снимают управление.
На паузе ходьба/прыжок заблокированы.

Угол: 0° вправо, 90° вверх, 180° влево. При смене команды прицел зеркалируется к сопернику.
Начальные 25° и 30% на равнине позволяют сразу увидеть попадание и воронку.
Во время полёта новые игровые команды закрыты; следующий ход появляется после стабилизации червей.

## Диагностика

- «Пауза» останавливает локальные шаги ядра; «+1 тик» делает ровно один шаг 1/60 секунды на паузе.
- Скорость 1×, 0.5×, 0.25× меняет темп вызовов step, сохраняя фиксированный dt ядра.
- «Сетка» включает линии через 16 клеток. «Коллизии» показывает реальные круги и центры червей.
- Журнал показывает последние 60 событий; счётчик хранит общее число событий текущего матча.
  Номер слева — тик доставленного снимка, события одного кадра могут быть сгруппированы.
  Подсказка строки содержит исходный JSON события.
- «Снимок состояния» показывает GameState. Большой bitmap заменён количеством твёрдых клеток
  и пометкой об исключённом массиве; это диагностическое представление, не снимок для загрузки.
- След и вспышка взрыва — эффекты от событий/позиций. Прицел показывает только направление,
  предсказания баллистической траектории нет.

В скрытой вкладке симуляция не продвигается. После торможения кадра адаптер обрабатывает не более 250 мс,
остальное время отбрасывает. При паузе накопленное время очищается.
Это сознательные свойства локального полигона; сетевой режим будет получать авторитетное время сервера.

## Модули

| Файл | Ответственность |
| --- | --- |
| `src/session.ts` | Контракт GameSession и LocalSession; применение команд, доставка снимков/событий, локальные отладочные часы |
| `src/main.ts` | Браузерный bootstrap: подключает game-core, LocalSession, requestAnimationFrame и видимость вкладки |
| `src/app.ts` | mountGame(root, session, debug?): DOM-интерфейс, ввод, журнал и диагностические элементы |
| `src/controls.ts` | Удерживаемые направления, перевод ввода в команды и сброс управления |
| `src/renderer.ts` | Canvas-отрисовка снимка и визуальные эффекты событий; кэш картинки карты |
| `src/scenarios.ts` | Данные четырёх тестовых карт, состав игроков и начальные настройки |
| `public/` | HTML, CSS и import map ядра |
| `test/session.test.mjs` | Проверки локальных часов, команд, подписок, сброса и полного выстрела настоящим ядром |

GameSession предоставляет `state`, `send(action)` и `subscribe(listener)`.
Подписчик сразу получает текущее состояние. Каждое обновление содержит `state`, `events`, `reset`;
подписка возвращает функцию отписки. `send` возвращает код отказа ядра либо null при принятии.
Этот контракт пока синхронный и достаточен для локального адаптера. При введении сети потребуется
добавить асинхронные подтверждения, ошибки транспорта и состояние соединения.

LocalSession получает функции ядра через конструктор. Рендерер не вычисляет движение, урон
или исход матча; использует готовые позиции/события и публичные константы для масштаба отображения.
Карта на экране строится из того же bitmap, с которым ядро проверяет столкновения.
Фоновые холмы декоративны и не являются частью карты.

## Перенос в VS Code

1. Расширение открывает webview и загружает ту же сборку интерфейса.
2. В bootstrap вместо браузерного LocalSession подключается будущий сетевой адаптер сессии.
3. HTML-оболочка получает URI ресурсов через webview.asWebviewUri, localResourceRoots и CSP/nonce.
   Import map и точки входа адаптируются к этим URI; правила игры и renderer переписывать не нужно.
4. Сообщения расширению идут через отдельный мост; turn-ready используется для уведомлений,
   а актуальная очередь восстанавливается из снимка при открытии.
5. Локальные пауза/шаг/сброс остаются инструментами разработки и не управляют серверным матчем.

Сейчас VS Code API, CSP webview, мост, сетевой адаптер и уведомления не реализованы.
Это направление переноса, а не готовая совместимость webview.

## Проверка

`npm test` из корня сначала собирает оба пакета, затем запускает тесты ядра и клиента.
Для визуальной проверки: начать ход → выстрелить с начальными параметрами →
увидеть воронку и потерю HP у Мятных → дождаться их очереди.
Затем проверить паузу/+1 тик, новый матч на холмах и другой ветер.

## Полоса препятствий C1

Выбрать карту «Полоса препятствий» и нажать «Перезапустить матч», затем «Начать ход».
Коралловый червь появляется слева; двигаться вправо по ступенькам, затем прыгнуть через стену.
После схода со ступенек дождаться приземления перед прыжком. Дальше пройти под потолком
и перепрыгнуть яму. Включить «Коллизии» для проверки границ тел.

Проверить отпускание клавиш, переход на ползунок/другую вкладку во время движения, паузу
и окончание хода: при возврате червь не должен продолжать идти. Изменить размер окна,
кликнуть по полю и сверить направление прицела. Повторить выстрел и смену команды.

`test/controls.test.mjs` проверяет приоритет направлений, сброс/паузу/смену хода, повторы прыжка,
прохождение полосы командами через настоящую LocalSession и координаты прицела после resize.
Визуальная приёмка части C1 для G1 подтверждена пользователем 24 октября 2026.
Визуальная приёмка части G2 подтверждена пользователем 24 октября 2026. C1 завершён.

## Проверка G2

На равнине выстрелить с начальными параметрами: пострадавший червь получает импульс,
приземляется и останавливается; только затем передаётся ход. В журнале видны `knockback`,
`worm-landed` и `damage` с источником урона. Подписи над телами показывают потерю HP,
а «Коллизии» добавляют линии текущей скорости из состояния ядра.

Для самоподрыва: угол 90°, сила 0%. Для высокого падения: выбрать «Высота и падения»,
перезапустить матч, начать ход и пройти вправо с уступа. Урон от падения появляется один раз
при приземлении. Обычный прыжок на ровном месте безопасен. Локальная пауза/замедление доступны.

## Текущие ограничения

Нет сетевых соединений, сохранения/загрузки партий и постоянного хранения истории.
Перезапуск страницы теряет матч. Ресурсы статические, внешних CDN, шрифтов, аналитики и сетевых API нет.
