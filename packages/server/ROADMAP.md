# server — этапы разработки

Статус: S0 реализован — [запуск, API и проверки](README.md). TCP-приёмка подтверждена пользователем 24 октября 2026; S0 принят.
Общий порядок: [план проекта](../../docs/roadmap.md).
Это игровой сервер; scripts/dev.mjs остаётся раздачей файлов для разработки.

## S0. Процесс и соединение — готово и принято

Зависит от P0/P1; P0/P1 завершены: [контракт v1](../protocol/SPEC.md) и
[parseClientMessage/validateServerMessage](../protocol/README.md), G0 уже доступен.

- [x] Пакет, отдельные команды сборки/запуска, конфигурация адреса/порта.
- [x] Транспорт, handshake, проверка версии/структуры/размера сообщений.
- [x] Назначение личности на сервере и привязка к соединению; модель доверия LAN. Токены восстановления — P2/S2 по P0.
- [x] Журнал старта, подключения/отключения и отказов без секретов.

Готово: два клиента подключаются к игровому процессу; неверные сообщения отклоняются;
настройки позволяют явный запуск на localhost и LAN.

Проверено 24 октября 2026: настоящий node:http/ws через потоки в памяти, включая
два клиента, HTTP Upgrade, неверные кадры, таймаут hello, лимиты, ID, очередь и остановку.
CLI help/некорректная конфигурация проверены отдельными процессами.
Общий npm test: 111 проверок проходят, 1 TCP-проверка пропущена; ошибок нет.
Для сервера: 24 проверки проходят, 1 требует TCP.
- [x] TCP-приёмка: пользователь подтвердил прохождение npm run test:server:tcp в локальном терминале 24 октября 2026. S0 принят.
Проверка двух машин в LAN остаётся приёмкой S3/M5.

S0 не выдаёт resume-токены и не создаёт комнаты; post-handshake команды пока получают not-implemented.

## S1. Комнаты и авторитетный матч

Зависит от S0/P1; совместно с C2.

- [ ] Комната для двух игроков, создание/вход/выход, готовность и запуск.
- [ ] Последовательное применение dispatch с playerId из серверной сессии.
- [ ] Фиксированные шаги 60 Гц по серверным часам; ограниченная стратегия догоняющих шагов.
- [ ] Подтверждения, события и снимки с ограниченной частотой, независимо от частоты симуляции.
- [ ] Свободное waiting; resolving/победа определяются только ядром.
- [ ] Проверки чужого хода, неверной фазы, одновременных команд и закрытия клиента во время выстрела.

Готово: M2 проходит в двух браузерах, скрытие клиента не меняет скорость матча.

## S2. Долгая партия и переподключение

Зависит от P2/S1; совместно с C3.

- [ ] Выбрать политику отключения до/после старта хода, срок удержания места и очистку комнат.
- [ ] Восстановление игрока по токену и выдача актуального снимка.
- [ ] Повтор commandId без повторного действия; правила смены соединения игрока.
- [ ] Ограничение очереди медленного клиента, пересинхронизация снимком при отставании.
- [ ] Проверки обрыва до/после подтверждения выстрела, возврата в resolving и после победы.

Готово: переподключение сохраняет место/карту/очередь и не повторяет выстрел.
При хранении в памяти потеря матчей после рестарта явно документирована.

## S3. Эксплуатация LAN MVP

Зависит от S2/G3/P3.

- [ ] Проверенные лимиты комнат, соединений, команд и размера снимка.
- [ ] Измеренная нагрузка на целевой карте и поддерживаемое число матчей.
- [ ] Корректное завершение процесса и понятное состояние клиентов после остановки.
