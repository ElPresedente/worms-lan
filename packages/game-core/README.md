# @office-worms/game-core

Независимое TypeScript-ядро: правила матча, физика и состояние без UI, сети и VS Code.
В первом срезе два игрока и один червь у каждого. Графики нет; пример работает в терминале.

## Использование

После сборки пакет доступен другим workspace-пакетам по имени:

```ts
import { createGame, dispatch, step } from '@office-worms/game-core';

let state = createGame({ players: ['alice', 'bob'] });
const start = dispatch(state, { type: 'start-turn', playerId: 'alice' });
if (start.accepted) state = start.state;

const shot = dispatch(state, {
  type: 'fire', playerId: 'alice', angleDegrees: 45, power: 0.65,
});
if (shot.accepted) state = shot.state;

while (state.phase === 'resolving') {
  const result = step(state);
  state = result.state;
  // result.events — эффекты, урон, смерть и переход к следующему ходу.
}
```

## API

| Функция | Результат |
| --- | --- |
| `createGame(options)` | Начальное `GameState`; неверные настройки вызывают `RangeError` |
| `dispatch(state, action)` | `{ accepted: true, state, events }` либо `{ accepted: false, state, events: [], error }` |
| `step(state)` | `{ state, events }` после одного фиксированного шага |
| `createFlatTerrain(width?, height?, groundY?)` | Растровая карта, по умолчанию 320×180, земля от y=112 |

Параметры создания: `players` — два уникальных непустых ID; `terrain` — необязательная карта;
`spawnX` — две горизонтальные координаты появления (на поверхности); `turnDurationSeconds` — 1..300,
по умолчанию 60; `wind` — ускорение по X от −30 до 30, по умолчанию 0;
`health` — начальное здоровье 1..1000, по умолчанию 100.
Карта — сплошной row-major массив 0/1, от 32×32 до 2048×1024.

Команды: `start-turn`, `move`, `jump`, `fire`, `end-turn`. Все содержат `playerId`.
Выстрел принимает угол 0..180° (0 — вправо, 90 — вверх, 180 — влево)
и силу 0..1. Сила 0 соответствует минимальной скорости, а не неподвижному снаряду.
Отказ: `game-finished`, `wrong-player`, `wrong-phase` или `invalid-action`.

Основные события: `turn-started`, `shot-fired`, `explosion`, `damage`, `worm-died`,
`knockback`, `worm-landed`, `resolution-limit`, `turn-ended`, `turn-ready`, `game-finished`. Список типизирован в `src/types.ts`.
Начальная очередь читается из начального состояния; отдельного события при создании нет.

## Модель и правила первого среза

- `waiting → active → resolving → waiting/finished`; пропуск/таймаут на земле переводит active в waiting, в воздухе — в resolving до приземления.
- `tick` считает только активные шаги. Команды не продвигают время.
- Ось X направлена вправо, Y вниз; единица карты — одна клетка.
- Червь — круг радиуса 5. Снаряд — точка со swept-проверкой через каждые ≤0.5 клетки.
- Гравитация 60 клеток/с², базука 25..150 клеток/с, взрыв радиуса 24 и максимального урона 60.
- Урон линейно убывает с расстоянием до тела; стены не экранируют взрыв.
- Взрыв затрагивает стрелявшего. Его тело игнорируется снарядом только до первого выхода из него.
- После разрушения опоры черви падают; взрыв также сообщает им горизонтальный и вертикальный импульс. Падение за нижнюю границу убивает.
- Следующий ход появляется после завершения полёта, падений и горизонтального скольжения.
- Снаряд, покинувший боковую/нижнюю границу, исчезает. Верхняя граница открыта.
  Через 15 секунд полёта снаряд также исчезает, чтобы выстрел всегда завершался.
- Последняя живая команда побеждает; одновременная гибель — ничья (`winnerId: null` при finished).
- Состояние и события — обычные JSON-данные. Входные объекты не изменяются;
  результаты могут разделять неизменяемые данные, поэтому потребитель тоже не должен их менять.
- Типизированный API принимает проверенные объекты. Проверка произвольного сетевого JSON
  и снимков при загрузке должна выполняться на границе protocol/server.
  `version: 1` пока обозначает формат состояния; миграций нет.

Обмен импульсами при столкновении тел, другое оружие, несколько червей и сетевой протокол пока не реализованы.
Параметры физики — начальные значения для проверки цикла, баланс ещё предстоит настроить.
Полная копия растровой карты на каждом активном шаге упрощает неизменяемость;
оптимизация памяти и производительности нужна перед увеличением карт/числа комнат.

## G1: движение и прыжок

```ts
// Начать движение; направление удерживается между тиками.
const moving = dispatch(state, { type: 'move', playerId: 'alice', direction: 1 });
if (moving.accepted) state = moving.state;
state = step(state).state;
// direction: -1 — влево, 0 — остановиться, 1 — вправо.
const jumping = dispatch(state, { type: 'jump', playerId: 'alice' });
if (jumping.accepted) state = jumping.state;
```

- Только живой червь активного игрока в фазе `active` принимает движение и прыжок.
- `GameState.movementDirection` хранит направление; `pendingTurnEnd` — причину окончания
  хода, ожидающего завершения физики. Эти данные входят в JSON-снимок; скрытого управления нет.
- `MOVEMENT`: скорость 24 клетки/с, начальная скорость прыжка 38 клеток/с вверх,
  максимальный подъём при обходе препятствия 2 клетки. Экспортируется из ядра.
- Направлением можно управлять и в воздухе. Инерции ходьбы нет. Повтор прыжка до приземления
  возвращает `invalid-action`. Команды не тратят тики и не создают отдельных событий движения:
  положение, скорость и `grounded` читаются из состояния.
- Перемещение проверяется по осям с шагом не больше 0.25 клетки. Стены и потолки блокируют тело.
  На земле допускается подъём по рельефу с поиском свободного положения выше на 0.25..2 клетки;
  вертикальный подъём тоже должен быть свободен. Так проходятся растровые ступеньки и уклоны;
  ограничения по углу склона отдельно нет. Спуск с уступа выполняется под действием гравитации.
- Живые черви — непроницаемые круги. Автоматически взбираться на тело нельзя; перепрыгивать
  и приземляться сверху можно. Мёртвые тела не мешают. Выталкивания и обмена импульсами пока нет.
- Боковые границы ограничивают тело целиком; верх открыт. Падение за низ карты убивает.
- Выстрел, пропуск, таймаут и завершение игры сбрасывают направление и горизонтальную скорость.
  Прыжок/падение продолжаются в `resolving`; `turn-ended` с исходной причиной и `turn-ready`
  появляются после стабилизации. При гибели от выхода за карту без выстрела причина — `pass`.
- Снимки G0 без новых полей не поддерживаются: создать новый матч. Версия остаётся разработческой
  `1`; фиксация формата и миграций предусмотрена G3.

Проверки G1: `test/movement.test.mjs`; общий запуск из корня — `npm test`.
Управление и тестовая полоса подключены в C1; визуальная приёмка подтверждена пользователем 24 октября 2026. G1 завершён.

## G2: взрыв, отбрасывание и падения

- Радиус действия совпадает с радиусом взрыва. Расстояние до тела: `d = max(0, расстояние_до_центра - 5)`.
  Сила импульса `55 * max(0, 1 - d / 24)` клеток/с; направление — от центра взрыва,
  с минимальной вертикальной составляющей вверх 0.35 перед нормализацией.
  При совпадении центров импульс направлен вверх. Стены не экранируют импульс.
  Погибший от самого взрыва червь импульс не получает.
- В `resolving` горизонтальная скорость сохраняется в `Worm.velocity.x`. Затухание линейное:
  8 клеток/с² в воздухе, 90 на земле, без смены знака. Столкновение обнуляет скорость по заблокированной
  оси, без отскока, передачи импульса и дополнительного урона от бокового удара. Автоступеньки
  разрешены только при управляемой ходьбе, а не при отбрасывании.
- При приземлении на рельеф или живое тело урон равен `min(100, max(0, floor((vY - 45) * 1)))`,
  где `vY` — вертикальная скорость непосредственно перед остановкой (клеток/с).
  Урон ограничен оставшимся HP. Обычный прыжок со скоростью 38 безопасен.
  Скорость обнуляется при ударе, поэтому следующий тик на опоре не начисляет урон повторно.
- Новые события: `knockback { wormId, velocity }`, `worm-landed { wormId, impactSpeed }`.
  `damage` теперь содержит `cause`: `explosion`, `fall`, `out-of-bounds` или `resolution-limit`.
  Приземление идёт перед уроном и возможной смертью, затем проверяется завершение хода/матча.
- Стабильность: все живые тела имеют опору, `grounded: true` и нулевую скорость по обеим осям,
  снаряд отсутствует. Смена очереди до завершения скольжения исключена.
- `GameState.resolvingTicks` считает только тики фазы `resolving`, сбрасывается при её начале/окончании
  и входит в JSON-снимок. Все данные продолжения симуляции находятся в состоянии.
- Аварийный предел — `MAX_RESOLVING_TICKS = 1800` (30 секунд симуляции). Если последствия ещё не
  завершились, ядро выдаёт `resolution-limit`, удаляет снаряд, останавливает тела с опорой и убивает
  неподдерживаемые тела с причиной `resolution-limit`, затем завершает ход. Цепочки опор проверяются
  повторно. Это защита от зависания, а не обычный игровой таймер; в проверенных сценариях не срабатывает.
- Публичные параметры: `FALL`, `KNOCKBACK`, `MAX_RESOLVING_TICKS`. Баланс пока предварительный.
  Снимки до G2 без `resolvingTicks` нужно заменить новым матчем; миграций пока нет.

Проверки: `test/physics.test.mjs`, включая неизменяемый вход и JSON-продолжение после взрыва.
В клиенте есть подписи урона/приземления, векторы скорости в режиме «Коллизии» и карта «Высота и падения».
G2 проверен автоматически; визуальная приёмка G2/C1 подтверждена пользователем 24 октября 2026. G2 завершён.

## Визуальная проверка

Браузерный полигон находится в [соседнем пакете client](../client/README.md).
Из корня проекта: `npm run dev`, затем http://127.0.0.1:4173.
Он вызывает это же ядро через локальный адаптер и показывает карту, снаряд, разрушения, HP и события.
Изменения исходников ядра автоматически пересобираются; страница при этом перезапускает матч.
